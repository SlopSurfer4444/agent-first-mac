# Workstation lifecycle

This public example is not installed or active and supplies no runtime manifest,
root permission or native consent. Adapt it to an established local control
contract before installing it.

Inspect the requested target and its actual primary installation/update owner.
Preserve canonical applications, data and unrelated settings; do not reinstall
merely to adopt management.

Project-local dependencies, builds, tests and commits use project contracts and
lockfiles. Do not invent workstation admission or control registration for them.

The owner may change software independently. Observation does not adopt an app,
trust code or authorize execution. Create durable managed intent only when the
owner requests control ownership; disposable experiments need no permanent
manifest merely to exist.

Reuse the host's scoped lifecycle adapter. Bind requested scope, source, affected
state, relevant capability checks and recovery. Match review to consequences,
not a fixed phase pipeline. Unknown relevant state pauses only that operation.
Never overwrite unknown changes or blindly retry possibly live work.

Protected policy, root, credentials, network exposure and native trust retain
their actual authority/consent boundaries. Do not substitute another installer
or broad privilege grant when the approved route refuses.

Verify affected behavior and recovery/no-op contracts. Distinguish source tests,
builds, installed state and observed functionality. A metadata observation is not
health, an old receipt is not fresh evidence and an example is not authority.
