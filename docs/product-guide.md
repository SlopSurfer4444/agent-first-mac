# Product guide

The owner operates their own computer. The harness makes requested agent work
predictable; it does not approve every owner action.

## Everyday work

Project edits, local dependencies, builds, tests and commits use the project's
contract and lockfiles. They need no workstation doctor, custom registration or
receipt merely because an agent performs them. Native permissions and
unknown-code precautions remain separate.

For an installed app, identify its actual primary installation/update owner.
Vendor, App Store and owner-managed software can coexist with managed intent.
Seeing an application is an observation, not adoption or permission to run it.
Only deliberate durable control ownership creates a persistent declaration.

## Monitoring without gatekeeping

The deterministic helper observes bounded filesystem metadata and keeps private
comparison records. It does not call a model, repair apps, authorize changes or
prove whole-machine health. Status reads retained observations; capture is a
separate action. Stale, unavailable, busy, external changes and unknown state
must not be relabeled as health.

The reference facade exposes `aid maintenance status [--json]` and
`aid maintenance schedule-status [--json]` as read-only routes. They do not scan,
install a scheduler or repair a host. These are source interface descriptions,
not commands that make this public checkout an operational installation.

An operation checks its affected dependencies at its own boundary. An unrelated
app does not become a prerequisite for editing a project or fixing another
component. Scheduler installation and an actual scheduled cycle are separate
from source availability and unit tests.

## Review the boundaries, not only the happy path

The 2026-10-19 review snapshot includes affected-source admission for
owner-authorized user helpers. Static imports, deferred imports, literal helper
and data references, and declared dynamic inputs form a conservative closure.
Unrelated notes or commits should not invalidate an operation; changed affected
inputs, import shadowing and replaced targets must still be rejected. A source
check is not owner authorization, root admission or native consent.

The latest source also binds executable entrypoints and their local imports
before helper effects. Review preloaded modules, import shadowing, changed source
between observation and use, and bounded child-process settlement rather than
assuming a recorded source hash proves what executed. Shared command custody and
launcher file operations are separated from unrelated delivery policy to avoid
expanding a small operation into the entire historical dependency graph.

Exact opaque data inputs are still held and checked even when their contents are
not interpreted as executable dependencies. Inspect each caller's declarations:
excluding dormant history is useful only if consumed inputs remain covered.

Delivery consumers include scheduler, quarantine file delivery, guidance and
root bundle staging. Their affected-source and exact-target checks must not be
confused with the explicit full vendor-compatibility diagnostic. Quarantine file
delivery is not permission to execute unknown code; staging a root bundle is
not installation or a privilege grant. Inspect the actual callers as well as
the shared readiness API: an unused scoped API cannot remove a blocking caller.

Custody records include durable transaction and reboot/namespace handling.
Settled retained records with matching provenance can survive device renumbering;
unknown provenance and ambiguous interrupted writes are not silently adopted.
Retaining unknown material rather than adopting or deleting it is intentional; unnecessary global
blocking, unrecoverable retained state and routine manual intervention remain
valid review questions. Distinguish cooperative same-user recovery from a
security boundary against a hostile process with the same user identity.

The typed administrator's Git observer drops to the bound user's identity
before Git interprets repository configuration. Review this separately from
user-helper source closure and from the root operation's target/receipt checks;
none is a substitute for the others. The selected Python suite does not execute
or certify the Swift broker's native privilege-drop behavior.

The optional RustDesk tunnel is a fixed loopback SSH adapter. Its source and
mocked tests are included; its private host declaration and actual authentication
state are not. Socket/listener checks do not prove screen or input usability.

This public tree omits the installed operational skill, host manifests and
private acceptance history. The example skill is illustrative, not a copy of
the installed skill. Findings about source control flow can be grounded here;
claims about the owner's current live policy or installation require separate
evidence. Missing excluded inputs are publication limitations, not by themselves
proof that the installed harness is broken.

## Changes and recovery

Bind a change to one target, one primary owner and a bounded recovery path. Reuse
the existing lifecycle adapter. Preserve unrelated settings and unknown concurrent
changes. Unproven relevant state pauses the affected operation, not unrelated work.

Protected trust, root policy, credentials and native permissions retain their
real review/consent boundaries. Recovery restores an operation's known state,
not somebody else's entire configuration; unknown drift is not declared safe.

## Optional subsystems and portability

Windows SSH and Wine/game launchers are optional integrations, not requirements
for ordinary development or monitoring. No operational host policy, games, saves,
Wine builds or remote credentials are supplied.

A fresh Mac still needs local component declarations, native permission/trust
decisions, reviewed delivery, protected-state setup and functional/recovery
acceptance. There is no supported installer. Missing original receipts must
never be fabricated to make an integration check pass.
